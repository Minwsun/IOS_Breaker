License notices are retained beside the assets: Tailwind, AOS, and Feather each have their upstream MIT `LICENSE` file; Font Awesome's `LICENSE.txt` contains its applicable code, icon, and font licenses. Font Awesome's stylesheet is kept intact, with every WOFF2 and TTF font URL it declares available locally. The page uses only Font Awesome's solid `info-circle`; the other faces are present for the stylesheet's declared compatibility support.

Tailwind remains the browser Play CDN runtime rather than a generated stylesheet. This preserves the current class generation behavior without adding a build toolchain. The snapshot is locally pinned by the version in its filename and SHA-256 because the original Play CDN URL itself is unversioned.

## Remaining outbound navigation

The page has no remote script, stylesheet, image, icon, font, or profile-configuration request at render time. The Locket profile download now targets `assets/locket.mobileconfig`. Remaining external destinations are user-initiated links: the App Store listing; the displayed raw GitHub config and module URLs (including ShadowRocket deep links that hand those URLs to the app); the account-provider sites; Instagram, Telegram, and the contact/payment profile. The ShadowRocket color customization link uses the app's `shadowrocket://` scheme. These are navigation or app handoffs, not website runtime assets.

## Self-hosted Sub-Store frontend

The Sub-Store frontend release 2.34.1 is served from `assets/sub-store/` at `https://minwsun.github.io/IOS_Breaker/assets/sub-store/`. The upstream release is pinned to tag `2.34.1`, commit `8dc19320894a9dbb3569e8bf3e41057491e39b90`. Its official `dist.zip` was fetched from the release URL over HTTPS (HTTP 200, 2,437,313 bytes, SHA-256 `b8116df45fe061987c9bce09d15adc8f8e311134e9105be040b94db43ebc433d`). The upstream source archive is retained at `vendor/sources/Sub-Store-Front-End-2.34.1.tar.gz` (1,299,533 bytes, SHA-256 `293c07e3cf339456336920fa5186ab990127319a7db0ed5b0ee18eb8f305c077`), with the upstream GPL-3.0 license in `licenses/Sub-Store-Front-End-GPL-3.0.txt`.

The distribution ZIP was checked for absolute paths, traversal components, duplicate paths, and symlink entries before extraction. The upstream release files are otherwise kept intact. Nine generated files have small local deployment-path edits: `index.html`, `index.js`, `css/main.css`, `chunks/main-bc07a4ee.js`, `chunks/actionsToPorcess-37c4d10b.js`, `registerSW.js`, `sw.js`, `manifests.json`, and `manifest.webmanifest`. These edits set the GitHub Pages base, make asset and preloader URLs relative to the app directory, and constrain PWA routing and service-worker scope to that directory. For each extracted file, `vendor/sub-store-frontend-lock.json` records its final SHA-256; the nine patched files also record their original release-entry SHA-256 and the local change description. The lock additionally records the source archive and license-file hashes.

The upstream production frontend defaults to the backend API at `https://sub.store`. It also accepts an `api` query parameter, so the frontend can be opened with `?api=https%3A%2F%2Fsub.store`; the frontend validates that backend by requesting `/api/utils/env` and persists the selected API locally. The backend must allow the GitHub Pages origin `https://minwsun.github.io` through CORS. This API traffic is an intentional runtime service dependency; scripts, styles, fonts, images, and app-shell files are served from this repository. GitHub API access is used only by optional in-app GitHub features. The About/settings screens also contain user-initiated GitHub and Telegram links; they do not load runtime code.
